# 人工视觉验收清单

实验原型，非正式业务工程。请在微信开发者工具模拟器中操作，不要让助手代替你切换系统外观。

路径：导入或打开 `experiments/p1-uniapp-probe/dist/build/mp-weixin`。改完代码后请先点开发者工具的编译/刷新，确认顶栏标题是「跟随系统」，再测切换。

底栏四个入口：**主题 / 首页 / 次页 / 原生**。

微信端只跟随系统，没有应用内浅色 / 深色开关。

## 建议顺序

1. 打开 **主题** 页，确认文案是「跟随系统」，并记下当前系统外观。
2. 在模拟器顶部把系统外观从 **浅色切到深色**，停在主题页，看会不会先闪浅色。
3. 保持深色，依次点 **首页、次页、原生、主题**，看第一帧。
4. 再把系统外观从 **深色切回浅色**，重复切页。
5. 在深色和浅色下各打开一次原生弹窗，并点一次输入框看键盘。

## 请判断的项目

| 编号 | 看什么 | 怎样算可接受 | 怎样记限制 |
| --- | --- | --- | --- |
| V1 | 系统浅色 / 深色下，首页/次页业务区 | 背景、顶栏、卡片、文字明显换成对应外观；浅切深能进深色，深切浅能回浅色 | 单向能切、反向停住，或只有文案变了 |
| V2 | 系统由浅切深、深切浅时，当前页第一眼 | 没有明显先闪错色再变过来 | 先闪白/浅色或先闪深色再变过来 |
| V3 | 切到首页、次页的第一帧 | 第一眼就是当前系统外观 | 先闪错色再变过来 |
| V4 | 底栏（原生 tabBar） | 背景和选中态与当前系统外观大致同向 | 底栏一直维持浅色或一直深色 |
| V5 | 自定义顶栏 | 顶栏背景和标题颜色跟页面走 | 顶栏颜色落后于页面 |
| V6 | 原生弹窗 | 能打开 | 弹窗颜色不跟页面，记为原生限制 |
| V7 | 键盘 | 能唤起 | 键盘颜色不跟页面，记为原生限制 |

不要求逐像素对比旧版。真机和 iOS 不是这次必做项。

看完后直接告诉我：哪几条通过、系统亮切暗是否还闪、弹窗和键盘是否跟外观。

## 人工结果（2026-09-11）

用户判定：开发者工具模拟器与真机均通过。未另报浅切深/深切浅单向失败，也未另报残留闪色。iOS 未单独声明。
