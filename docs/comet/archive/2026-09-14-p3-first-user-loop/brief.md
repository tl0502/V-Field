# Outcome

P3 范围与新增用户号需求（2026-09-14）。用户已明确确认上一 session 的完整 P3 范围，并补充在 UUID 之外增加便于用户互搜和管理平台检索的 userid。用户已选择固定 8 位随机数字、全平台唯一且不可修改；当前没有业务验收通过声明。

目标是在新版中打通「指定域运营者 → 申请入域 → 审批 → 成员发布 → 访客阅读」，并纳入作者删除自己的已发布内容，以及独立于内部 UUID 的公开用户号和用户互搜。

上一 session 按用户要求重新核对了本 change 原 brief 和 spec，并逐项取得 Q1–Q10 答案；不能用初稿自己的“已确认”“本轮默认”替代真实决定。Q9 确认 P3 交付域运营者可用的最小规则配置闭环；Q10 选择域成员可创建、域运营者新增/查看/停用的共享标签库。本 session 用户明确表示“我确认该范围”，该确认包含上次提交的数值、初始化及交互细则。新增 userid 替代原先让用户直接使用 UUID 的方案，其他已确认范围继续有效。

# Scope

## 完整范围

| 部分 | 本轮需要设计和交付到的程度 | 边界 |
| --- | --- | --- |
| 业务域用户前端 | 一套服务预置汽车验证域的首页列表、入域入口与状态、发布/预览、内容详情、作者删除入口；页面显示真实域身份 | 单个域足以验证首期闭环；不为每个未来行业分别做一套前端。数据、发布权和管理权仍按域隔离 |
| 平台后台 | 在平台账号中搜索目标用户、核对用户 ID、指定汽车域运营者；无管理凭证时生成随机密码并现场展示 | 与用户端共用账号；不扩成建域或完整用户治理后台 |
| 域后台 | 域运营者用用户 ID 和管理密码登录，处理本域入域申请，并创建/编辑/停用本域文章类型、选用平台模板、设置必用与数量规则 | Q9 已确认进入 P3；共用域管理入口，权限按域隔离 |
| 公开用户号与互搜 | 每个账号分配独立 userid；本人可查看/复制，用户端按完整用户号找人，平台后台按同一号码查找管理目标，域后台以该号码登录 | UUID 保留为内部主键；提供最小公开识别结果，不扩为完整个人主页、昵称/手机号搜索或社交关系 |
| Block | 平台提供正文与自由描述车源卡片模板；明确模板字段/版本、编辑/阅读形态，以及域规则允许控制的范围 | 平台模板编写与目录管理后台后置，不等于域运营者选用模板、配置文章类型规则也后置 |
| 编辑器 | 按文章类型读取域规则，复用标题、正文穿插多车源卡片、卡片编辑/移除/换位、本地草稿、预览与发布；支持标签复用和新建 | 自由描述、无图片、无到期和车源状态；每账号每域一份本地草稿 |
| 文章展示 | 明确列表摘要、详情的标题/作者/所属域/发布时间/正文/卡片，及加载、空、失败、内容不可读状态 | 删除后的旧链接不可继续读正文；不把旧联系方式、评论或作者占位文案当成真实能力 |
| 发布与删除 | 正式域成员发布，正文可独立发布、车源卡片可选；作者删除整篇内容 | 无图片/对象存储；作者不能更新已发布标题、正文、卡片或卡片状态；不增加独立下架/恢复工作流 |
| 入域状态 | 未申请、待审、已批准、已拒绝、已取消及其可用操作 | 待审不重复提交，申请者可取消；拒绝后可重新申请；取消后回到可申请状态 |
| 数据与运行基础 | 补齐公开用户号分配、互搜、账号管理查询、用户号登录及申请取消，以及内容、域文章类型、Block 规则、版本与域标签库 | 当前 vflie 是用户授权查看、修改及必要清理的测试数据库；本次新增用户号优先通过增量迁移补齐 |
| 标签 | 成员选择已有词或随发布创建，域运营者新增/查看/停用本域标签；列表/详情展示 | 同域共享、同名复用；停用只限制后续使用；标签不控制 Block 结构 |

Q9 已确认的域级最小配置能力是：在本域创建/编辑/停用文章类型，选用平台内置模板，设置允许使用、是否必用和数量上下限；编辑器与服务端使用同一规则。平台提供的模板字段和渲染方式不由域运营者任意改写。

上述原 P3 范围与下列既有细则已由用户在本 session 确认；新增用户号采用用户已选择的固定 8 位随机数字。保留旧 UI 的布局、视觉和主要交互，不等于继承旧发布校验、汽车业务规则、占位承诺或数据结构。首期之外的旧功能仍保留在整体恢复清单中。
